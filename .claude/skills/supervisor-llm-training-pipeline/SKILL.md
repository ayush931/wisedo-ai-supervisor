# Domain-specific LLM training pipeline

Source: `docs/adr/agentic-ai-docs/0004-oee-intelligence-llm-training-pipeline.md`.
**Status: proposed.** Scope WIS-234. Prerequisites ADR 0002 and ADR 0003.
The infrastructure that implements this lives in `deploy/aws/` — see the `supervisor-aws-training`
skill. Governing rules: `.claude/rules/08-untrusted-input-and-model-boundary.md`,
`.claude/rules/09-verification-gates-and-evidence-claims.md`.

> **NON-GOAL:** the model does not replace the deterministic calculation kernel. It explains and
> analyzes; it does not compute. The system never fabricates metrics, and generation is unavailable
> until an approved policy and golden vectors exist.

## Why fine-tune

Generic models lack manufacturing and OEE domain knowledge, hallucinate formulas, mis-aggregate
across windows and lines, and misread plant-specific downtime taxonomies.

Target capabilities: OEE formula reasoning (A×P×Q, TEEP, the Six Big Losses); downtime root-cause
analysis from plant-specific reason codes; `CalculationPolicyV1` interpretation; evidence
explanation from an `OeeEvidencePackV1`; readiness reasoning over `NOT_READY`/`LIMITED`/`INVALID`
codes with actionable remediation; and multi-shift, multi-line comparison.

## Model selection — open weights only

Commercial closed-source APIs are **explicitly excluded** for data sovereignty, air-gap readiness,
zero third-party licensing exposure and plant-telemetry privacy.

| Tier | Choice |
| --- | --- |
| Development, prototyping, edge | Llama 3.1 8B with QLoRA (4-bit) — single commodity GPU |
| Production primary (self-hosted) | Llama 3.1 70B with LoRA, or Qwen 2.5 72B for advanced math/logic |
| High-throughput serving | Mixtral 8x7B (MoE) or Llama 3.1 8B AWQ 4-bit |
| Degraded-mode fallback | A self-hosted quantized standby (Llama 3.1 8B AWQ) inside the private VPC — **never** an external proprietary API |

## Training data

Five sources: sealed evidence packs; calculation policies; the downtime taxonomy; synthetic Q&A
generated by self-hosted open teacher models plus deterministic template engines; and quality
filtering by deduplication, format validation and LLM-as-a-judge completeness scoring.

Anonymization strips `tenant_id`, user and actor references, equipment serial numbers and
proprietary shift names. `tenant_id`, `actor_id` and JWT claims are banned from the corpus outright.
No production secrets, connection strings or API keys ever reach the training cluster.

## Infrastructure

Nightly export from PostgreSQL → S3 data lake → preprocessing → SageMaker/HyperPod GPU training →
evaluation suite → model registry → EKS vLLM serving. All cloud resources are declarative Terraform
under `deploy/aws/`; Python is reserved for training execution inside containers. Versioned immutable
S3 buckets with SSE-KMS. FSDP or DeepSpeed ZeRO-3 for 70B. Experiment tracking records loss curves,
learning rates, GPU utilization and generation samples. CI/CD triggers: monthly S3 aggregation, a
substantial calculation-policy revision, or manual dispatch.

## Evaluation gates

| Domain benchmark | Threshold | Method |
| --- | --- | --- |
| OEE formula accuracy | 95% | exact match |
| Readiness reasoning | 90% | expert review + LLM judge |
| Downtime classification | 92% | exact match |
| Policy interpretation | 85% | LLM judge |
| Evidence explanation | 88% | ROUGE + expert review |
| Hallucination rate | **< 2%** | automated detection |
| Cross-tenant leakage | **0%** | adversarial testing |

General benchmarks guard against catastrophic forgetting: MMLU must not drop more than 5% relative
to base, HellaSwag more than 3%, GSM8K and ARC within 5%.

Pipeline: automated harness plus custom domain scripts immediately after training; a self-hosted
open judge model for conversational outputs against sealed ground-truth packs; expert review for
major versions. **Only models passing all gates are promoted to the staging registry.**

## Serving and security

vLLM (or TGI/Triton) with GPTQ/AWQ quantization. The serving endpoint sits behind the internal
network under the same OIDC auth as the core. Tenant context is injected via the system prompt by
the agent harness, never by the user. Model weights live in private registries with IAM-restricted
download. Inference requests and responses are logged asynchronously with tenant context.

GDPR: if a tenant exercises erasure, an automated impact analysis determines whether their
anonymized data materially influenced the current model, and if so triggers retraining on a newly
sanitized dataset. Training and serving nodes stay inside approved regions.

## Cost

Per training run roughly $45–90 for 8B and $525–1,125 for 70B. Monthly inference roughly $180
(dev, 1× A10G) to $3,200 (production, 1× p4d.24xlarge) and ~$6,500 for multi-AZ HA. Optimizations:
spot instances (up to 70% saving), semantic caching in front of the inference server, and
progressive routing of simple queries to the 8B model.

## Delivery order

1. Training data pipeline (anonymization, formatting, quality filtering). 2. Base model validation
on early synthetics. 3. QLoRA prototype on 8B with ~10K pairs. 4. Automated domain benchmark suite.
5. Scale to 50K–200K pairs and iterate on data mixture. 6. Full LoRA training on 70B.
7. vLLM serving on EKS with Karpenter. 8. Shadow deployment and A/B against live traffic.
9. General availability with monitoring and automated cost controls.

## Change control

Promoting a model version requires a documented pass from the automated evaluation suite. Changing
the training data distribution or source logic requires re-evaluation against historical baselines.
A new foundation model requires a complete retraining pipeline execution and human-in-the-loop
validation.
